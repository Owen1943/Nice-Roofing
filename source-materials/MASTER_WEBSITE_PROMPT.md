## Stack, architecture, performance
Preferred stack: **Next.js App Router + React + TypeScript + Tailwind CSS + shadcn/ui**, with disciplined components, typed content, accessible primitives and minimal dependencies. Keep content in typed local data/MDX for launch, with a documented path to an optional CMS. Avoid an unnecessary database if the website only showcases products and emails enquiries. Use an audited form delivery provider or server-side SMTP integration; do not expose keys. Structure to add CMS/product updates later without rewriting design.

Satisfy infrastructure goals **without performative overengineering**:
- CDN for immutable images/static assets; optimized cache keys; long-lived hashed assets; sensible server-side page cache and `stale-while-revalidate`/ISR for public content with clear revalidation. **Never cache POST enquiries, PII or admin/private responses**. Document purge/invalidation.
- Edge **reverse proxy** (e.g. Nginx/Caddy/managed ingress) with trusted-proxy configuration, strict HTTPS, correct forwarding headers, bounded payload limits, upstream timeouts and compression.
- **Load balancing**: design stateless application replicas and readiness/health probes behind a managed load balancer/ingress, only scale to multiple replicas where host supports it. No sticky session dependency for forms.
- **API gateway** at the edge/ingress for `/api/*` endpoints for request limits, schema/versioning and access policies; don't invent separate microservices to justify a product name.
- **Rate limiting**: central shared store (e.g. Redis/Upstash) across instances at app/API level plus managed edge limits; conservative rate controls on contact submission, adaptive protections, distinct limits for legitimate users; robust headers/IP handling behind trusted proxies.
- **Docker**: multi-stage reproducible production Dockerfile, small non-root runtime, pinned supported base image, `.dockerignore`, no secrets baked into image, healthcheck. A working `docker compose` dev/preview stack (app + Redis if used + reverse proxy where meaningful), `.env.example`.
- **CI/CD**: GitHub Actions (or repository-native equivalent) running format/lint/types/unit/integration/build, a11y/SEO smoke checks, dependency/security scanning, container scanning/SBOM, build-and-push tagged image, staging deployment, controlled protected production promotion, rollback strategy; use OIDC or least-privilege deploy credentials. Configure branch protections where available.
- No domain/cloud credentials supplied? Deliver functional local Docker environment and **provider-neutral staging/production infrastructure diagrams + deploy instructions**, clearly marking cloud-specific settings. Do NOT claim external production is deployed.
- Error observability: structured logs that exclude PII; meaningful metrics (response latency, 4xx/5xx, form success/failure counts, rate-limit hits), error monitoring, uptime/health checks and documented alerts.
